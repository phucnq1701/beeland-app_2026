# Inventory B — Sales services (beeland-app_2026)

Scope: `sevicesSupabase/BookingService.ts`, `DatCocService.ts`, `HopDongService.ts`, `PaymentGatewayService.ts`,
`PaymentProgressService.ts`, `SigningService.ts`, `LichHenService.ts`, `ReportService.ts`, plus the shared helper
`sevicesSupabase/customerLookup.ts` (only the parts these services call) and the lib helpers they use for payloads/parsing
(`lib/listRpc.ts`, `lib/bookingPrice.ts`, `lib/bookingPayload.ts`, `lib/bookingState.ts`, `lib/bookingProgress.ts`,
`lib/depositQr.ts`, `lib/qrPaymentState.ts`, `lib/paymentMath.ts`, `lib/signing.ts`, `lib/reportDetail.ts`, `lib/countdown.ts`).
`lib/qrPaymentState.ts`, `lib/countdown.ts`, `lib/bookingProgress.ts`, `lib/bookingState.ts`, `lib/depositQr.ts`, `lib/reportPeriod.ts` make **no network calls** (pure).

Transport: all calls go through `axiosApiSupabase` (baseURL `https://api-beeland26.beesky.vn`). `rest/v1/*` ⇒ `Authorization: Bearer <cloud JWT>` (falls back to anon key silently if JWT expired);
`functions/v1/*` ⇒ `Authorization: Bearer <@token>` (legacy session token). Exception: one `fetch` to `https://upload.beesky.vn/api/Upload` (legacy .NET upload, outside api-beeland26).

Abbrev.: `companyId` = tenant uuid from JWT/AsyncStorage (`getCompanyId`), `companyCode` = lowercase company code (`getCompanyCode`).
"Used fields" = fields the app actually reads (traced through mappers → screens). Fields mapped but never read are listed under Notes as "unused".

## 10. Top issues for the new app-only endpoints

1. **Money/deadline decided on the device.** Booking: `tien_giu_cho`, `het_han_luc`, all price fields (B11, B15 → B12); lock: duration, expiry, voucher number via count (B2, B43 → B45); QR VA amount/expiry/customer name (B52 / route-param `TienCoc−DaThu` → G2). Server must compute these; app should send only ids (product, customer, sàn, lock id / pgc id, VA account `ma_tk`).
2. **Non-atomic multi-step writes + client cron.** `createLock` = RPC status change (B44) then direct INSERT (B45) — a failed insert leaves the unit locked with no record. `sweepExpiredLocks` (B48+B49) is run by every device, PATCHes rows one by one, and never returns product 18→2. `expireSweep` (G4) is also client-triggered. → `POST /locks` (atomic) + server-side expiry job.
